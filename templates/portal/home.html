Built for Real-World Cricket Engineering

Most sports datasets break on cricket edge cases. CricPulse is engineered with strict domain invariants to deliver mathematically accurate statistics.

🏏

Strict Overs Notation

Overs formatted as (balls // 6) + ((balls % 6) / 10.0) so the decimal is strictly 0 to 5 (e.g. Bumrah at 605.1 overs, never 605.7).

👑

Official Cap Invariants

Orange Cap strictly excludes wide balls from balls faced; Super Overs are excluded from player aggregate totals. Purple Cap counts only bowler-credited dismissals.

🏟️

Uncorrupted Venue Par Scores

Stadium scoring benchmarks are computed strictly on completed/bowled-out innings (≥ 19 overs or 10 wickets) so rain-shortened DLS matches never skew stadium par.

🛡️

Sliding-Window Rate Limiting

In-memory sliding window enforcing 60 requests/min per IP with periodic pruning to prevent memory exhaustion under 512MB RAM cloud constraints.

⚡

DuckDB Columnar Speed

Analytical SQL aggregations run directly on Apache Parquet files using zero-copy DuckDB execution, finishing complex group-bys in milliseconds.

🔑

Cryptographic Developer Keys

Generate, roll, and revoke 24-byte hex tokens (cric_live_...) directly through this Django developer portal with administrative revocation.
